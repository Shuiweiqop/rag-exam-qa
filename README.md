# RAG Exam Q&A System

A retrieval-augmented generation (RAG) system for answering exam-style questions from course material. Given a question, it retrieves the most relevant passages from a knowledge base and generates a grounded answer **with a cited source**, so every answer can be traced back to the material it came from.

Built as a hands-on project to go deep on the RAG pipeline end to end — not just wiring an API, but understanding and measuring retrieval quality.

## Why this project

Most RAG demos stop at "it returns an answer." The part that actually matters — and that most demos skip — is **whether the retrieval is any good**. Because exam questions come with known correct answers (past-year papers, textbook exercises), this project can *quantify* retrieval quality instead of eyeballing it. Evaluation is the core focus, not an afterthought.

## Tech stack

- **Python 3.13** + **FastAPI** — REST API layer
- **Google Gemini** (`gemini-embedding-001` for embeddings, `gemini-2.5-flash` for generation)
- **PostgreSQL + pgvector** (hosted on Supabase) — vector storage and similarity search
- **psycopg2** — database driver

## How it works

```
Question
   ↓  embed (gemini-embedding-001, 3072-dim)
Query vector
   ↓  cosine distance search in pgvector (<=>)
Top-k relevant passages
   ↓  stuffed into a grounded prompt
Gemini (gemini-2.5-flash)
   ↓
Answer + cited source passage
```

The prompt explicitly instructs the model to answer **only** from the retrieved passages and not to rely on its own knowledge — this is the key to preventing hallucination.

## API

| Method | Endpoint  | Description                                              |
|--------|-----------|---------------------------------------------------------|
| POST   | `/upload` | Embed a piece of text and store it in the knowledge base |
| POST   | `/ask`    | Retrieve the most relevant passage and generate an answer with its source |

Interactive API docs are auto-generated by FastAPI at `/docs`.

### Example

Request to `/ask`:

```json
{ "question": "What is the relationship between the sides of a right triangle?" }
```

Response:

```json
{
  "question": "What is the relationship between the sides of a right triangle?",
  "answer": "The square of the two legs of a right triangle sums to the square of the hypotenuse.",
  "source": "The Pythagorean theorem states: the sum of the squares of the two legs of a right triangle equals the square of the hypotenuse.",
  "distance": 0.16
}
```

Note that the question never mentions "Pythagorean theorem" by name — retrieval finds it by meaning, not keywords.

## Setup

1. Create and activate a virtual environment:
   ```bash
   python -m venv env
   env\Scripts\activate      # Windows
   ```
2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```
3. Create a `.env` file with your credentials:
   ```
   GEMINI_API_KEY=your_key
   DB_HOST=your_supabase_host
   DB_PORT=6543
   DB_NAME=postgres
   DB_USER=your_db_user
   DB_PASSWORD=your_db_password
   ```
4. Enable pgvector and create the table (run in Supabase SQL editor):
   ```sql
   create extension if not exists vector;
   create table documents (
     id bigserial primary key,
     content text,
     embedding vector(3072)
   );
   ```
5. Run the API:
   ```bash
   uvicorn main:app --reload
   ```
   Open `http://127.0.0.1:8000/docs` to try it.

## Notes

- `gemini-embedding-001` outputs 3072-dimensional vectors by default; the pgvector column is sized to match.
- Questions and documents must be embedded with the same model and dimensions, or they won't share a comparable vector space.
